# VTT Stable-Parity Gauntlet Ledger

## Gauntlet Charter

- **Outcome:** One GM and multiple players can prepare and run an engine-native
  virtual tabletop covering the audited stable AboveVTT user jobs without
  importing AboveVTT implementation expression.
- **Deliverable:** The Python VTT services, SQLite aggregates, browser client,
  original assets, tests, and operator documentation in this repository.
- **Primary bar:** The clean-room stable-feature evidence and decision report in
  `docs/specs/`, interpreted through this repository's authoritative engine and
  security architecture.
- **Hard gates:** Server authority; deterministic replay and restart recovery;
  authentication before protected-input validation; audience-safe projections;
  bounded media and geometry; stable non-leaking errors; keyboard-accessible and
  reduced-motion-aware browser workflows; Black, backend tests, browser build,
  browser tests, ESLint, and `git diff --check`.
- **Evidence:** Focused contract/store/API tests, full VTT regression suite,
  browser unit and rendered-source tests, build/lint output, restart fixtures,
  privacy assertions, and fresh-context critic verdicts.
- **Operating envelope:** One local or protected table per composed app; SQLite
  durability; current desktop evergreen browsers; static PNG/JPEG/WebP maps up
  to 12 MiB and 64 million pixels; bounded finite scene geometry; hundreds, not
  tens of thousands, of scene tokens; D&D engine positions expressed in feet.
- **Constraints / non-goals:** Clean-room comparison only; do not copy upstream
  source, assets, identifiers, algorithms, schemas, or visual expression. Do not
  ingest remote media or entitlement-gated content. Beta-only upstream features
  do not block stable parity unless explicitly promoted.
- **Finding promotion rule:** A concern becomes active only when it reproduces in
  changed code, links to a hard gate or supported stable job, is reachable inside
  the operating envelope, and has a proportionate acceptance check. Credible
  privacy, security, data-loss, or legal harm may interrupt immediately.
- **Backlog sink:** `docs/vtt_gauntlet_backlog.md`.
- **Critic budget:** One fresh critic pass plus one focused re-review for each
  feature workstream; one final integrated critic plus one focused re-review.
- **Stop control:** Stop only after all scoped stable-feature hard gates pass and
  the final independent critic accepts the integrated result, or at an explicit
  user checkpoint.
- **Autonomy:** Routine architecture, implementation, testing, and corrective
  work are autonomous. Escalate only material product choices, authority
  expansion, destructive actions, or changes to the clean-room boundary.
